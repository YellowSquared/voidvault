The Three-Channel Pipeline

How physical silicon, browser runtime isolation, and blind network relays work in harmony.

Phase 1
🔑

Physical Silicon Evaluation

When you touch your YubiKey, the browser invokes the W3C WebAuthn prf extension (CTAP2 hmac-secret). The key evaluates an HMAC over a deterministic salt inside the tamper-resistant hardware chip. Master keys never leave the silicon.

  • Origin-bound RP ID protection
  • Phishing immunity: fake sites get useless random output
  • No master password to remember or type
Phase 2
💻

Volatile In-Memory Decryption

The 32-byte hardware PRF secret enters browser memory. WebCrypto HKDF derives:
1. Non-extractable AES-256-GCM vault encryption key.
2. Ed25519 signing keypair for self-certifying writes.

  • Marked extractable: false (DOM scripts cannot export key)
  • Capsule decrypted strictly in volatile RAM
  • Automatic 15-minute auto-lock scrubs all memory
Phase 3
🌐

Blind Bit-Bucket Relay

The relay server (Axum + SQLite) acts as an untrusted blind storage locker. It indexes records purely by the SHA-256 hash of the client's public key (self-certifying locator).

  • Monotonic anti-rollback state defense (409 Conflict)
  • Sliding-window IP rate limiting against spam
  • Cryptographic alias delegation for secondary backup keys

Why VoidVault vs. Linux pass?

Preserving the beloved Unix philosophy while eliminating the fatal metadata leakage of Git.

❌ When You Sync Linux pass to Git:

While passwords inside each .gpg file are encrypted, Git and the server see your entire directory hierarchy in plaintext:

# Git server & network eavesdropper sees:
~/.password-store/
├── banking/
│   ├── chase.com.gpg       ← Leaks: You bank at Chase
│   └── schwab.com.gpg      ← Leaks: You have a Schwab brokerage
├── medical/
│   └── cancer-center.gpg   ← Leaks: Highly sensitive health history
└── adult/
    └── secrets.gpg         ← Leaks: Personal lifestyle metadata
⚠️ Anyone with read access to the Git repo or server logs knows every bank, hospital, and service you use.
✅ How VoidVault Fixes It:

VoidVault stores secrets in the exact same Unix multiline format, but wraps everything into a Single Unified Encrypted Blob Capsule:

# VoidVault server & network eavesdropper sees:
voidvault-server / SQLite:
└── 7b8e1f4a9b2c3d4e5f60... (SHA-256 Locator):
    └── [ 1 opaque AES-256-GCM ciphertext blob ]
        - 0 service names
        - 0 folder paths
        - 0 entry counts
        - Padded discrete sizing
🔒 Zero metadata leaked. Plus: 1-click bi-directional export back to standard Unix pass anytime!

Quickstart & Deployment

Spin up your own private, air-gapped, or public blind relay in seconds.

Production-grade rootless container managed natively as a systemd service:

# 1. Clone main branch
git clone -b main https://github.com/YellowSquared/voidvault.git
cd voidvault

# 2. Run the turnkey Quadlet installer
./quadlet/install.sh

# 3. Verify daemon status under user systemd
systemctl --user status voidvault.service

Standard Docker container with persistent SQLite volume:

# 1. Clone main branch
git clone -b main https://github.com/YellowSquared/voidvault.git
cd voidvault

# 2. Launch with Docker Compose
docker compose up -d

# 3. Verify health endpoint
curl http://localhost:8080/health

Compile and run directly with the Rust toolchain:

# 1. Clone main branch
git clone -b main https://github.com/YellowSquared/voidvault.git
cd voidvault/server

# 2. Run the test suite (18 unit & integration tests)
cargo test

# 3. Launch the high-performance release server
cargo run --release

Install directly on Ubuntu, Debian, or Linux Mint:

# 1. Build or download the .deb package from releases
cd voidvault/server
cargo deb --no-build

# 2. Install via dpkg / apt
sudo dpkg -i target/debian/voidvault-server_0.2.0-1_amd64.deb

# 3. Service starts automatically via systemd
sudo systemctl status voidvault-server
